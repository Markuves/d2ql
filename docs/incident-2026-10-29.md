# Incidente 2026-10-29 — el sweep H4 nunca terminaba

Resumen: el servicio `python-agent` se reinició **65 veces en 26 h** sin completar el sweep H4.
50 reinicios fueron un bug determinista (FIX 1) y el resto, ausencia de tolerancia a fallos
(FIX 2-5). Este documento conserva la evidencia y las decisiones; las correcciones están en
`python-agent/d2ql/` (ver "Correcciones" abajo).

Las 50 muertes deterministas tienen causa conocida y corregida (FIX 1). Las **dos primeras**
(runs 0 y 1) terminaron sin traceback y son el objeto de la nota siguiente.

## Silent deaths — resolution

**Hipótesis del owner:** los contenedores de esos dos runs se detuvieron a mano (Ctrl-C /
`docker compose stop`), lo que produce exactamente esa firma: SIGTERM/SIGKILL no deja traceback
de Python.

**Evidencia de contenedores: no disponible (contenedores podados).** El motor Docker que ejecutó el
incidente (`unix:///var/run/docker.sock`, contexto `default`) ya no conserva ningún contenedor de
esa fecha. `docker ps -a` solo lista:

```
java-sim       Up 9 hours (healthy)   d2ql-java-sim       2026-11-02 00:05
tensorboard    Created                d2ql-tensorboard    2026-08-25 22:21
python-agent   Created                d2ql-python-agent   2026-08-25 22:21
```

El `python-agent` listado **no** es del incidente: `docker inspect` lo confirma como nunca iniciado
(creado 2026-08-25, `started=0001-01-01`, `finished=0001-01-01`, `status=created`), así que su exit
code no dice nada sobre los runs 0 y 1. **No se pudo leer ningún exit code de los runs del incidente**
(no hay 143, ni 137, ni `OOMKilled`). No se inventa un resultado: la comprobación pedida
(`docker inspect --format '{{.State.ExitCode}} OOMKilled={{.State.OOMKilled}} {{.State.StartedAt}} {{.State.FinishedAt}}'`)
no es aplicable porque los contenedores ya no existen.

**Evidencia indirecta que sí se conservó (de los logs):**

1. El último registro del run 1 es una línea normal de entrenamiento en `stderr`, sin excepción ni
   resumen de sweep:
   ```
   2026-10-29 03:33:11,359 [INFO] Episode 60/400 | Reward: -256.9272 | Steps: 1100 | ... | Cloudlets: 50
   ```
   Un proceso que muere por excepción habría dejado traceback (como los 50 runs con `TypeError`);
   esta firma es compatible con una señal externa.
2. Diez minutos después (03:43:22) los runs 2-9 fallan con `socket.gaierror` porque **el nombre
   `java-sim` ya no resuelve**: el stack completo había sido derribado y recreado. Un crash del
   `python-agent` no elimina el DNS de `java-sim`; un `docker compose down` / `up` sí. Eso es la
   firma de una parada y rearranque manual del stack.

**Conclusión:** la hipótesis de parada manual es **consistente** con toda la evidencia disponible
(última línea sin traceback + stack recreado diez minutos después) pero **no queda probada**, porque
los exit codes se perdieron al podarse los contenedores. No hay evidencia de OOM en esos dos runs.

**Salvaguarda residual (se mantiene, no se debilita):** la instrumentación del FIX 6 sigue activa para
que cualquier muerte silenciosa *futura* sea diagnosticable:

* `-Xlog:gc*:file=/app/logs/gc.log` (rotación 5 × 20 MB) y
  `-XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/app/logs/heapdump.hprof` en `java-sim`, dentro del
  volumen `java-logs` (`docker compose cp java-sim:/app/logs ./java-logs`).
* Retención de logs de `python-agent` subida a `100m × 5` (antes `10m × 3`, que descartaba la evidencia
  del reinicio anterior).
* Healthcheck de `java-sim` que verifica que el puerto 25333 acepta conexiones, no solo que el proceso viva.

Si vuelve a ocurrir una muerte sin traceback: revisar `docker compose ps -a` para el exit code
(143 = SIGTERM, 137 = SIGKILL), `OOMKilled`, y `docker compose cp java-sim:/app/logs`, antes de recrear
los contenedores; recrear los borra.

## Correcciones aplicadas (rama del incidente)

| FIX | Qué | Dónde |
|---|---|---|
| 1 | `config_sha256` normaliza claves a `str` (el `TypeError` de las 50 muertes) | `python-agent/d2ql/provenance.py` |
| 2 | Aislamiento por celda en el sweep: una celda que falla se registra y el sweep continúa | `python-agent/d2ql/train.py` |
| 3 | `--resume` salta celdas con `result.json` completo; cableado en `docker-compose.yml` | `train.py`, `docker-compose.yml` |
| 4 | Reintentos con backoff (1 s → 30 s, 10 intentos, jitter) en toda llamada Py4J | `python-agent/d2ql/env.py` |
| 5 | Un solo tipo de error (`GatewayError`) con contexto de episodio/cloudlets | `python-agent/d2ql/env.py` |
| 6 | GC logs, heap dump on OOM, retención de logs y healthcheck de puerto | `Dockerfile.java`, `docker-compose.yml` |
| 7 | Truncaciones por episodio a DEBUG + resumen INFO cada 50 episodios | `python-agent/d2ql/train.py` |
